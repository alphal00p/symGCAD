# Detailed usage and proof formats

See the [quick start](../README.md) and [dependency setup](SETUP.md) first. Commands in this guide run from the repository root. Experimental options are explicit; resource exhaustion is always an incomplete result.

## Problem format

```toml
name = "positive square split by F"
variables = ["x", "y"]
constraints = ["x > 0", "1-x > 0", "y > 0", "1-y > 0"]
split = ["x+y-a"]

[parameters]
a = "1/2"

[solver]
engine = "baseline"
ordering = "given"
order = ["x", "y"]
merge = "none"

[limits]
wall_time_secs = 300
memory_mib = 4096
workers = 1
```

Coefficients and parameter substitutions are exact rationals. Constraints use `<` or `>`; powers accept `^` or `**`. Expressions cannot introduce undeclared symbols or functions. `split` requests the signs of extra polynomials in each returned cell. Omitting it gives the ordinary strict-inequality problem.

Orders are written from the first lifted variable to the last; projection eliminates them in reverse. An explicit `order` fixes the order. Otherwise `ordering` accepts `given`, `mods`, `sotd`, `t1`, `brown`, `sparsity`, `mcts`, or `kinematic_portfolio`. Top-level `variable_groups = [["s", "t"], ["x", "y"]]` keeps the first group outside the second while allowing within-group choices.

`ordering = "kinematic_portfolio"` targets parametric Feynman-parameter inputs whose last variable group is exactly the `homogeneous_block` and whose earlier groups hold kinematic parameters. The candidates are the default MODS candidate, then every other certified homogeneous anchor and finally the input anchor, each combined with every within-group order of the kinematic variables (MODS still chooses the Feynman order). Orders lifting a decoupled kinematic variable (one that occurs only in polynomials of its own, such as `s` in `s > 4` when the Feynman polynomial depends on `t` only) before a coupled one are not probed: they give the same product kinematic decomposition and only add constant resultants. The supervising CLI does no algebra: the candidate enumeration (anchor certificates included) and every probe run in killable workers under hard wall budgets and the input's memory limit, so the input's limits hold, and the portfolio time is charged to the wall limit of the following `solve`, `project` or `order` worker. If the enumeration does not finish within the default probe budget, or anything else prevents the portfolio (including an invalid input), the default MODS order runs unchanged with the reason recorded, so a result is always written. The default probe gets `portfolio_default_budget_secs` (default a tenth of the wall limit, clamped to 1-60 s) and the others `max(portfolio_min_budget_secs, portfolio_budget_factor x default probe time)` (defaults 0.25 s and 2), tightened to `max(portfolio_min_budget_secs, portfolio_budget_factor x best probe time)` once a candidate beats the default; the whole portfolio is limited to `portfolio_total_budget_secs` (default a quarter of the wall limit). The default probe also lifts the complete fibers above `portfolio_fiber_samples` (default 8) evenly spread kinematic cells to estimate its lifting time, and the alternatives together stop after `portfolio_lifting_budget_factor` (default 1) times that estimate (0 samples disables this bound). If the default probe is not scored, its solve costs at least the probe time, so the unprobed alternatives evenly share `portfolio_lifting_budget_factor` times that time; only a default probe over the memory limit, which the default solve would exceed as well, leaves them the whole portfolio budget. These bounds limit the alternatives, not the default probe itself: when the default wins, the final solve recomputes its projection, so the overhead is the default probe (about the default's ordering and projection time) plus the alternatives' bound. On the 26 solved parametric corpus cases the lifting estimate was 0.41-0.73 times the solver's measured `lifting_seconds` (median 0.65), so the bound is conservative, and the largest regression was Cx12_438 (default kept; median wall 32 s to 60 s over three runs, its 23.6 s probe projection computed twice). `portfolio_fixed_budgets = true` instead gives every candidate the same budget `min(default budget, total budget / (candidates + 1))` with no tightening or lifting bound, so the choice depends on wall time only through which probes finish within that budget. This is reproducible but costly, since every candidate may use its whole budget: on the 26 solved cases one run took 1317 s in total, against 93 s for the adaptive budgets and 106 s for MODS (sums of medians of three runs), and it chose identically in two runs of 21 cases. On 40 further held-out corpus inputs the adaptive portfolio solved and verified four (A286, Ax286, C158, Cx158) whose default MODS solve exceeded 5 GiB, in 5.7-47.6 s; the 36 tiny ones paid 0.16 s each on average. A probe runs the solver's own preparation (positive scaling, sign filtering, monotone peeling, certified projection) and counts the exact open cells of the kinematic prefix with the solver's root isolation, up to `portfolio_kinematic_cell_cap`; probes never use `checkpoint_dir`. The fewest cells win, then the fewest projection terms, then enumeration order; if nothing is scored the default MODS order runs unchanged. The selected anchor and explicit order are written into the solved problem, which differs from the input only in `ordering`, `order` and `homogeneous_anchor`, so the ordinary solver and verifier check the result; the verifier refuses a result whose problem still requests the portfolio. `statistics.ordering_portfolio` records the enumeration and every candidate, budget and score (`project` and `order` outputs record it as `ordering_portfolio` with the chosen `homogeneous_anchor`); the portfolio time is included in `ordering_seconds` and `total_seconds`. An explicit `order` is never replaced, and other layouts or engines without a global projection fall back to MODS. Scores and budgets are predictions only: a timeout or a score never removes a region. Budgets are wall-clock limits, so on a heavily loaded machine the choice can differ between runs.

`symgcad project` exports the projection that `solve` itself lifts: with a homogeneous anchor it projects the positive-scale reduced problem (reported under `homogeneous`, with the anchor and the original lifting order), and the optimized engine uses the same ordering and certified-projection cache path as `solve`. `symgcad order` reports a chosen order, or the bounded search history for `mcts`. The search uses at most 256 trials by default and reserves most of the one-hour campaign for its selected solve. Timeouts never count as completed decompositions.

The `optimized` engine reuses canonical factorizations, resultants, and projection prefixes. `positivity = true` permits removal of generated factors only with exact nonvanishing certificates; `input_positivity = true` extends this to input factors while retaining coordinate boundaries. `checkpoint_dir = "artifacts/checkpoints"` enables atomic, validated persistent prefixes and individual algebra operations shared by ordering trials. Completed operations survive interruption halfway through a projection stage. MCTS enables this directory automatically and includes its search history and cost in the solve result.

MCTS also publishes a bounded atomic trial journal under `checkpoint_dir/searches`. Repeating the same problem with the same executable reconstructs the scheduler's RNG, tree visits and promotion state; an interrupted trial is retried. Context checks include normalized polynomials, domains, variable groups, solver options and executable identity. Historical completion claims appear as `unverified` until a fresh bounded solve succeeds, and never substitute for the final exported proof. Each invocation receives its configured wall budget; scheduler iterations remain bounded by `max_rollouts`, and revalidation calls share the current invocation's trial budget. Corrupt, incompatible or oversized journals are ignored with a reported reason. The journal is capped at 8 MiB and 4,096 records; unsupported persistence bounds leave ordinary bounded search available.

The certificate portfolio includes bounded exact Sturm tests for univariate factors, including open and unbounded domains. Optional `prune_operations = true` attempts a nonvanishing proof before factoring an entire projection operation; it requires positivity and retains explicit original-boundary obligations. It defaults off because the additional proof attempt can cost time without succeeding. Both kinds of omission carry independently replayed evidence.

One-parameter resultants and discriminants first try exact evaluation/interpolation. Its image count is a proved degree bound plus one: the smaller of the closed-form Sylvester bounds and the exact assignment (tropical) bound of the Sylvester matrix. The assignment bound is the checked dual value of LP potentials proposed by the Hungarian method, so it does not rely on that search. A plan whose closed-form bound is at most 1024 lies in the historical envelope and keeps the historical caps and their dynamic image stops. Every other plan, including one brought under 1024 only by the assignment bound, is admitted only when an a-priori Hadamard bit bound of every integer image, and of all images together, fits the image caps, so no dynamic resource stop can occur after such an admission. Each image is an exact integer resultant; an image whose specialized operands share a factor is decided to be zero by an exact gcd test (a modular gcd modulo a fixed prime that keeps both degrees proves coprimality, otherwise Symbolica's integer gcd decides) and Lazard-Ducos is never called on it, because Symbolica 3.0.1 panics there (`patches/symbolica-ducos-zero-subresultant.patch`). Every interpolated or segmented result is then spot-checked at one further full-degree point through Symbolica's own specialization and its Brown subresultant resultant over Q, a route these kernels do not use; a mismatch is an error. Nothing is probabilistic. `binary_resultants` enables exact binary segmentation for eligible pair resultants in the optimized and local projection caches. It defaults on since the 2026-10-12 kernel measurements; set `binary_resultants = false` to opt out. Pair applicability requires exactly two surviving active parameters and at most 8,192 combined input terms and 256 million encoded output bits; all degree, coefficient and encoding bounds are checked before large allocations. The same flag also enables discriminants with one or two surviving parameters after the existing bounded interpolation strategy statically declines, retaining the same size caps and exact signed leading-coefficient division. Other inputs retain the ordinary exact backend. Once an eligible computation starts, cancellation or an error propagates without starting another expensive method. The worker deadline remains binding. Reports separately count segmented pairs and discriminants, with their largest encoded-output bound; completed operations share the existing exact algebra checkpoints. Local proof replay freshly recomputes opted-in discriminants without discovery caches. Baseline projection, global proof replay and pair-resultant replay keep their ordinary backend. The [bounded-operand policy](../reference/BINARY_SEGMENTATION_RESULTANTS.md#larger-bounded-operands) explains the resource envelope; the [discriminant study](../reference/A377_BINARY_DISCRIMINANT_DIAGNOSTIC.md) records independent signed verification and the remaining factorization cost.

Bounded square-plus-positive-residual certificates also handle polynomials whose coefficient signs alone are inconclusive. They record the exact square, residual and bound orientations, including affine squares after a homogeneous scale is fixed. Verification reconstructs the identity on the original domain. The algebra backend additionally detects small polynomials depending on two variables through their sum, factors in fewer active variables, and checks the inverse substitution and complete factor product. This preserves the original CAD coordinates; see [the captured A446 factorization experiment](../reference/SUM_FACTOR_PRECONDITIONING.md).

The default-off `solver.affine_factorization = true` enables bounded coordinate preconditioning for factorization. An exact regular-fiber test first selects a candidate evaluation point. Nonzero diagonal scaling reaches that point while preserving monomial support; integer translation remains available when scaling fails its admission or resource checks. A separate bounded shear policy handles eligible remaining inputs. Every selected transformation is inverted exactly, and both transformed and original signed factor products are reconstructed with full variable maps and multiplicities. Only one native factor call is made for the selected transformation: a blocked call remains subject to the worker deadline. Scaling can increase coefficient costs, so its measured operand successes are not a universal speedup claim. See [diagonal scaling](../reference/DIAGONAL_FACTORIZATION_RESEARCH.md).

By default, `search_pruning = true` abandons ordering trials when completed projection prefixes show severe term growth and avoids repeating that prefix within the current search. These are cost predictions: they never reject a mathematical region, and the final solve does not use them. Set the option to false for the search ablation. When no trial completes, the result stays incomplete and retains a restart candidate. `SYMGCAD_CAPTURE_DIR` optionally records exact operands and timing for the latest uncached operation in each worker; captures are bounded to 16 MiB and can be replayed with `cargo run --example profile_operation` to compare existing Symbolica resultant strategies.

The opt-in `search_local_progress = true` ranks timed-out local-engine candidates for longer trial budgets using observed polynomial inventory and refinement growth. It defaults to false. Each distinct registered polynomial contributes once to the polynomial/term counts and maximum total degree/coefficient bit height; the score sums `ln(1+x)` over those four counters and the refinement count. Smaller scores are promoted first within the existing timeout tiers. This is an uncalibrated cost prediction, not a coverage estimate: it changes neither UCT rewards, mathematical pruning, nor completed-winner selection. Old reports have no such score. Journals bind the option and scoring-policy version, and progress diagnostics never enter proof verification.

In a [three-pair release experiment](../reference/LOCAL_SEARCH_PROMOTION_BENCHMARK.md), local promotion scoring verified the reduced Gluza30 base in all three runs at a median 65.10 seconds including search; the same search with scoring disabled remained incomplete at 313.62 seconds. This result applies to that workload; the option remains off by default.

An explicit `homogeneous_block = ["x1", "x2", "x3"]` with `homogeneous_anchor = "x2"` requests positive-scale reduction. The engine checks every constraint and split polynomial, proves the anchor positive, and reconstructs the original cylindrical boundaries. A fixed order must place the anchor before the other block variables. Nonhomogeneous inputs or incompatible fixed orders are rejected.

The `monotone` engine accepts one split polynomial and detects positive-axis variables where exact linear/quadratic coefficient certificates prove strict increase and positive unbounded growth. It solves the endpoint problem using the optimized engine by default; `solver.monotone_base_engine = "local"` selects local projection for that exact base problem. It then reconstructs every positive root sector. Its proof contains the coefficient certificates, exact endpoint identities, and complete base decomposition. Additional constraints involving a peeled variable prevent that peel; fixed orders and variable groups remain binding. This engine composes with homogeneous scale reconstruction.

For an unsplit problem (`split = []`), `engine = "monotone"` transfers the first non-coordinate-affine strict constraint into a complete sign arrangement and retains exactly the required sign cells. For example, `constraints = ["z>0", "z^2+z-1<0"]` decomposes the increasing polynomial `z^2+z-1` and selects its negative cells while preserving the original inequality and empty split annotation. A projection-free check of admissible first peels chooses the split orientation; it respects fixed orders and variable groups. The `sign_filter` proof records the orientation, selected sign, full arrangement, and exhaustive selection map. Verification reconstructs the signed polynomial identity without rerunning that heuristic and preserves all exceptional seams. Historical evidence defaults to its original positive orientation and selection. This wrapper also composes with homogeneous reduction and local endpoint solving. Inputs containing only coordinate-affine or constant constraints receive an explicit applicability error.

For an unsplit monotone problem, the opt-in `solver.monotone_negative_target = true` can solve a strict constraint `Q > 0` directly by orienting `F = -Q`. A certified increasing positive-ray peel reduces the required negative fiber to its strict endpoint inequality, then restores only the interval below its positive root. Separate target evidence verifies the original inequality and exhaustive coverage. Requested homogeneous reduction applies to the original constrained problem before this target transfer. If no admissible target peel exists, the ordinary sign-filter arrangement remains the fallback. Existing split-polynomial arrangements are unchanged. The research campaign helper exposes the same option as `--monotone-negative-target`.

The opt-in `linear_negative` engine handles an unsplit problem with exactly one non-coordinate strict target and all variables strictly positive. For a target linear in `z`, `q=A*z+B<0`, an optional `negative_linear_guide = "..."` proposes `U=C*z+D`: the engine must independently prove `C,D>0` and the exact identity `B*C-A*D = k*H^2` with rational `k>=0`. The guide adds no domain assumption. These checks reduce the target to `A<0` and restore `z>max(0,-B/A)`. A globally certified negative `A` also permits this restoration without a guide. Fixed orders and variable groups remain binding; additional non-coordinate constraints and homogeneous anchors are currently unsupported.

```toml
variables = ["x", "z"]
constraints = ["x>0", "z>0", "(x-1)*z+x<0"]
split = []

[solver]
engine = "linear_negative"
ordering = "given"
negative_linear_guide = "z+1"
```

Restored lower boundaries use the polynomial `z*q` with `index_domain = "real_descending"` and index zero: the largest **distinct** real root, including zero. This represents the continuous boundary `max(0,-B/A)` even when its two roots coincide at `B=0`. A dedicated `linear_negative` certificate proves the identities, exact base problem and exhaustive restoration; the selector itself does not assert ordinary simple-root delineability. Verify its exported JSON with the same `symgcad verify` command.

The opt-in `bilinear_positive` engine treats the final two axes of a given order as `y,x` in a strict target `a*x*y+b*x+c*y+d>0`. It checks seven strict positivity certificates for a proposed `bilinear_positive_guide`, decomposes the signs of `a,b,c` in the remaining variables, and reconstructs every admissible positive fiber using ordinary linear-root bounds. All coordinates must be positive and unbounded; other domain constraints, homogeneous anchors and identically zero `a,b,c` are currently unsupported. `bilinear_positive_base_engine` selects `baseline`, `optimized` (default), or `local`. The [small TOML example](../examples/bilinear_positive.toml) produces two verified cells. The [proof and Gluza research note](../reference/GLUZA30_POSITIVE_LADDER.md) explains the exhaustive cases and independently verified positive Gluza30 result; an incomplete base never becomes a complete original result.

The opt-in `bilinear_general` engine handles the same target shape `a*x*y+b*x+c*y+d>0` (final axes `y,x`, both strictly positive) for all 16 strict sign patterns of `a,b,c,d`. Base-only constraints are retained. An identically zero `a` or `Delta=b*c-a*d` is refused. An identically zero `b`, `c` or `d` has no zero set in the open quadrant, so the fiber table uses the sign of its partner (`a*y+0` has the sign of `a`, `c*y+0` that of `c`, `0*y+d` that of `d`); a zero coefficient carries no premise, condition or split.

The optional `bilinear_general_guide` proposes `U=u_a*x*y+u_b*x+u_c*y+u_d`. Planning certifies `u_*>0` on the coordinate box and searches, by Symbolica square-free decomposition, for typed ratio premises `upper*u_lower-lower*u_upper = m*s^2` with `m>0`; pointwise these give `lower>0 => upper>0` and `upper<0 => lower<0`. A pair whose product exceeds the term cap is skipped, not an error. The separator `G` orders the two breakpoints `-b/a`, `-d/c`: `Delta = m*G^2` (Delta>0 off `G=0`), `Delta = -m*G^2` (Delta<0 off `G=0`), or `G=Delta` itself. Global strict signs use ordinary domain certificates.

The planner enumerates branching orders over the atoms `a,b,c,d,G`. `bilinear_general_plan_objective` chooses among the resulting plans:

* `region_weighted` (default) minimizes atom polynomials per piece, each weighted by the number of premise-consistent sign regions the piece covers. It avoids carrying an atom over a region where another sign already fixes it. On Gluza33 this gives the four `b,c` sign-quadrant pieces of the structure analysis (weighted cost 28, plain count 11).
* `atoms` minimizes the plain number of atom polynomials over all pieces. On Gluza33 it merges `{b<0,c>0}` and `{b<0,c<0,d>0}` into `{b<0,d>0}` split `c` (3 pieces, plain count 9, weighted cost 30).

Which plan is cheaper to solve is an empirical question per base engine. The verifier accepts any valid plan, whichever objective produced it.

Each piece is an ordinary problem: the retained base constraints, then strict atom conditions in canonical order, with leaf atoms as splits. `bilinear_general_base_engine` selects `baseline`, `optimized` (default) or `local`. `bilinear_general_base_anchor` applies a homogeneous anchor inside every piece. Its scale block is `bilinear_general_base_block` (base variables only), or every base variable when that list is empty. The anchor must precede the other block variables in the base order, so a kinematic parameter can stay outside the block. The verifier replays every identity and certificate, checks with a truth table over all premise-consistent strict sign vectors that the pieces and empty claims partition the base and that each leaf decides the fiber table, verifies each piece with the ordinary verifier, and rebuilds every cell. Atom zero sets and coordinates are part of the exceptional set. Each piece's own verifier proves that its cells are sign-invariant on the split atoms: split factors are protected boundaries in every base engine.

Pieces can run as separate processes:

```bash
symgcad pieces plan input.toml --out-dir pieces          # pieces/piece_NNN.toml + pieces/plan.json
symgcad solve pieces/piece_000.toml -o r0.json             # one process per piece, in any order
symgcad pieces assemble input.toml --plan pieces/plan.json --results r*.json --output result.json
symgcad verify result.json
```

`pieces plan` and `pieces assemble` run in worker processes bounded by the input's `limits` (wall time and memory), like `solve`. `pieces plan` removes stale `piece_NNN.toml` files of an earlier plan from a reused `--out-dir` and lists them as `removed_stale`. Assembly matches each result to its exact piece problem and refuses duplicate, missing or foreign results.

`solve` with `engine = "bilinear_general"` runs the same plan sequentially. See the [small TOML example](../examples/bilinear_general.toml).

Timings stay distinct. `statistics.bilinear_general_pieces` records `execution`, the planning time, every piece result's own `total_seconds` (`piece_seconds`), their sum and maximum, and `assembly_seconds`. With `execution = "sequential"` (`solve`), `total_seconds` is the elapsed time of the whole solve and the phase timings include the pieces; planning is counted in `ordering_seconds`. With `execution = "separate_processes"` (`pieces assemble`), `total_seconds` and the phase timings cover only the assembly process. `piece_seconds_sum` is then the sequential-equivalent piece time, not elapsed time; pieces solved concurrently take at least `piece_seconds_max`. Each embedded piece result keeps its own statistics.

The experimental `local` engine uses a generic-open stack-saturation adaptation of Strzeboński's local projection. Descendant guards refine their owning ancestors, all sibling boundary sets are projected jointly, and the verifier checks the resulting exhaustive tree independently. It supports explicit/given orders and inexpensive Brown/sparsity orders; MCTS supplies explicit trial orders. Other ordering requests have an explicit global fallback. Persistent algebra caches and progress snapshots survive interrupted discovery. With `positivity = true`, exact domain certificates can replace generated guards; their original bound factors remain protected ancestor obligations, proving the certificate's premises throughout the cell. Input factors and singular seams remain protected. The exceptional polynomial list is a global algebraic superset; the local tree records where each excluded section actually applies.

On an axis with an original strict positivity constraint, local projection can use exact quadratic sign cases or Descartes sign variations to avoid unnecessary discriminants. Zero variations imply no positive roots; one variation implies exactly one simple positive root. The latter boundary uses `index_domain = "positive"` and index zero, so collisions among negative roots cannot change its meaning. Other boundaries retain indices among all distinct real roots (the default `index_domain = "real"`). Typed evidence rejects the negative half-line explicitly and propagates every coefficient-sign premise to the ancestors. Inconclusive higher-degree cases retain the ordinary projection obligations. `solver.local_descartes_one = false` disables the one-variation shortcut; `LocalOptions::positive_ray = false` retains the full-real-line path for library ablations.

The experimental `solver.local_descartes_witnesses = true` extends this argument to two through eight positive roots. It requires a Descartes upper bound of exactly that many roots and alternating strict signs at rational separators between the isolated roots. Every coefficient and separator evaluation becomes an ancestor guard, proving that each interval contains exactly one simple positive root throughout the parent cell. These boundaries use positive-root ordinals. The attempt is capped at degree 32 and defaults to 4,096 source terms. `solver.local_descartes_witness_max_terms = 8192` explicitly changes that source budget; values from 1 through 65,536 are supported, with the identical limit used for discovery, template reuse and independent verification. Historical evidence retains 4,096. Reports distinguish `descartes_witness_source_term_fallbacks` from exhausted template stock. There are still at most two separator sets per canonical polynomial for the entire solve. Existing sets are reused when valid; unsuccessful or exhausted attempts retain the ordinary discriminant. This finite stock prevents repeated separator selection from creating an infinite sequence of new guards near colliding roots. Separator guards can still increase the number of cells, so witnesses remain off by default. A larger source budget does not bound the subsequent ancestor projection cost; the [measured guard-cost gate](../reference/GLUZA33_WITNESS_BUDGET.md) is an algebra diagnostic, not a completed solve.

The separate opt-in `solver.local_descartes_intervals = true` also handles unsaturated global Descartes bounds. It covers the entire positive ray by rational intervals, transforms each finite interval to the positive ray, and certifies zero or one sign variation per interval. Strict guards protect every transformed coefficient, finite seam, original endpoint, and leading coefficient. The independent verifier reconstructs these identities and the complete cover from typed evidence. This proves zero through eight simple positive branches without assumptions about negative roots. By default, the attempt retains at most two permanent covers per polynomial, in addition to the two global separator sets if both options are enabled. `solver.local_descartes_interval_template_limit = 8` permits a larger fixed stock; values from 2 through 8 are supported, and missing historical options retain 2. Every successful admission consumes a slot for the entire solve, even if its tentative stack later fails; cache eviction cannot replenish the stock. Existing valid covers remain reusable after the limit is reached. Exhausted or inconclusive attempts retain the ordinary discriminant. Local reports record the configured limit, admissions, reuses and budget fallbacks. Source admission defaults to 4,096 terms; `solver.local_descartes_interval_max_terms = 32768` explicitly permits larger sources, with supported values from 1 through 65,536. Omitted historical options retain 4,096. Discovery, permanent-template reuse and independent supplied-cover replay share this limit. It changes only source admission: bounds still include degree 32, 4,096 terms per canonical guard, 256 coefficient slots and distinct guards, and a default of 65,536 total guard terms. `descartes_interval_source_term_fallbacks` records source declines separately from permanent-template exhaustion. See the [bounded guard measurement](../reference/GLUZA33_INTERVAL_BUDGET.md). Rational endpoint height is capped at 256 bits and primitive guard coefficient height at 512 bits. The option remains off by default because the extra ancestor guards can increase the decomposition size.

The separate `solver.local_descartes_interval_max_total_terms = 131072` permits a larger sum of terms across the distinct canonical guards of one cover. Values from 1 through 262,144 are supported; omitted historical options retain 65,536. Discovery acceptance, permanent-template reuse and independent verification enforce the same recorded budget. Per-guard size, coefficient height, interval count, coefficient slots, endpoint guards and finite template limits remain unchanged. This is a resource allowance, not a positivity assumption or permission to remove roots. See the [measured guard costs](../reference/GLUZA33_FINAL_INTERVAL_FRONTIER.md).

Before constructing symbolic guards, interval discovery can merge adjacent pieces when an exact recount proves that their union still has zero or one sign variation, equal to their previous total. It never merges two root-containing pieces. The bounded pass removes unnecessary artificial separators; the verifier still reconstructs the complete positive-ray cover, all required guards and every interior root branch. Source budgets and the permanent template quota are unchanged.

The separate `solver.local_positive_pair_witnesses = true` option can replace a pair resultant after both polynomials' positive roots have been proved delineable. It protects every adjacent edge belonging to different polynomials with a rational separator and two nonvanishing evaluation guards. The verifier checks the complete positive-root order and each separator with exact root counts. Shared positive roots, failed checks or exhausted template stock retain the ordinary resultant; common negative roots do not invalidate a positive-ray certificate. Each pair has at most two templates for the entire solve. Attempts are limited to degree 32, 4,096 terms per polynomial, 16 positive roots total, eight cross-owner edges and 256 bits for a separator's numerator and denominator combined. This option also defaults to false.

Separator guards are new, sample-dependent polynomials: each must be projected at lower levels and can pair with further cuts, so templates for pairs whose resultant is small can inflate the cut sets instead of saving work. The opt-in `solver.local_pair_witness_min_resultant_terms` admits a new template only when the dense monomial bound of the replaced resultant (the Bezout total-degree bound `deg_z(p)·deg'(q) + deg_z(q)·deg'(p)` over the other occurring variables) exceeds the given value; the default 0 keeps the historical always-attempt policy, so existing inputs run and serialize unchanged. `solver.local_pair_witness_axis_budget` (default 0, unlimited) caps new templates per lifting axis for the whole solve. Both are discovery-only choices: a decline selects the ordinary resultant, which the verifier always accepts, and a nonzero value is recorded in local evidence only when witnesses are enabled (verifiers older than these fields reject such evidence). On the Gluza33 base piece `{a>0}` the historical policy spent 20.4M speculative nodes in 570 s without finishing; with the gate at 4096 it completes in 0.02 s with the same 178 verified cells. There, and on 19 of 20 measured corpus cases, the gate at 4096 admitted no template, i.e. it behaved like `local_positive_pair_witnesses = false`. Where it does admit templates it has not beaten disabling witnesses: symbolic `Ax12_6_190` completes in 0.03 s without witnesses but stays incomplete after 300 s with the gate (two admitted templates are reused for 62,341 omitted resultants), and on symbolic A446 and positive Gluza33 neither setting completes. See [the measurements](../reference/LOCAL_PROJECTION_LIVENESS.md).

For two positive-root-bearing polynomials, local projection also tests exact leading-term cancellation identities. If every coefficient of a nonzero combination has the same certified sign throughout the ancestor cell, the polynomials cannot share a positive root and their pair resultant can be omitted. At most two cancellations are attempted, with fixed multiplication-work bounds; inconclusive cases retain the resultant. The verifier reconstructs the identities and all sign obligations. Set `solver.local_pair_cancellations = 1` for the one-cancellation ablation, or `LocalOptions::positive_pair_separation = false` to disable the shortcut entirely.

The opt-in `solver.local_strict_bezout_hints` array proposes identities `p*L + q*M = k*H^2` for specific canonical factor pairs. Each table has `schema_version = 1`, `polynomials = [p, q]`, `multipliers = [L, M]`, `square = H`, and `multiplier = k`, with all polynomial and rational values written as strings. The solver checks the exact identity and requires `k > 0`; this initial implementation proves `H` strictly nonzero from uniform coefficient signs and original positive-coordinate constraints only. Earlier coordinate premises become explicit ancestor guards, and the current axis must have its own original positivity constraint. The certificate omits only the matching pair resultant; individual leading-coefficient, endpoint and delineability obligations remain. Invalid, unmatched or over-budget proposals retain ordinary projection. Proposals must use canonical factors in the chosen variable order, including any compensating scalar in `L` and `M`. Discovery is limited to 128 supplied hints and 4 MiB of text, with bounded polynomial and multiplication sizes. The independent verifier checks recorded identities without trusting the proposal list or any cache; an empty list preserves historical behavior.

For certified global projection (`positivity = true`, optimized engine), `solver.projection_strict_bezout_hints` accepts the same tables (`square = H`, so `S = H^2`) or `positive = S` in place of `square`. The identity `p*L + q*M = k*S` with `k > 0` is checked exactly, and `H` (respectively `S`, with sign `+1`) needs an exact `domain.rs` certificate on the open coordinate box of the original constraints. Then `p` and `q` never vanish together inside the box and `Res(p,q)` is omitted at every level where both appear; `p`, `q`, their leading coefficients and discriminants remain, and pairs involving a coordinate-affine face are never omitted. Polynomials are matched after canonicalization, so sign variants of one pair all match. Each omission is recorded as replayable evidence in `optimized_projection.pair_omissions`; the verifier rechecks the identity, the certificate against the original domain, the level, the axis and the pair's membership. Rejected proposals are counted in `pair_omission_hints_rejected` and never assumed. Hint and evidence texts are untrusted: on Symbolica's unnormalized parse tree, before anything is expanded or evaluated, a structural bound on every subexpression (sums add term counts, products multiply them, a power `f^e` of a `t`-term `f` has at most `C(t+e-1,e)` terms) must stay within 16,384 terms, total degree 64 and 65,536 coefficient bits, exponents must be integer literals and `k` a decimal rational literal. Short texts such as `(x+y+z+1)^300` or `7^(3^20)` are refused immediately; the expanded polynomials must then fit 4,096 terms. Each distinct proposal list is proved once per domain and certificate budget (`pair_omission_hint_checks` counts the checks), and an empty list clears any earlier configuration of a reused cache. Only engines with certified global projection use these hints: `optimized`, `linear_negative`, and `monotone` with `monotone_base_engine = "optimized"`; validation refuses them for every other engine rather than ignoring them (the local engine takes `local_strict_bezout_hints`). With `homogeneous_anchor`, projection runs on the positive-scale reduced problem, where the anchor is fixed to 1 and the other variables keep their names (as ratios to the anchor): hints must then be written in those reduced coordinates, i.e. dehomogenized at anchor = 1; a hint mentioning the anchor is rejected as an undeclared variable.

Local discovery can collect obligations from several siblings before rebuilding a stack. Every tentative stack with new cuts is discarded; only a fully saturated pass can produce certified cells. `solver.local_batch_siblings = false` restores one-sibling discovery for comparisons. Exact Sturm counts use a signed integer primitive pseudo-remainder sequence to control coefficient growth; positive normalization preserves every required one-sided endpoint sign.

Completed small local subtrees can be reused at the identical rational prefix within one solve. Their full ancestor obligations are returned and checked on every reuse. The cache retains bounded serialized proofs (at most 128 nodes and 1 MiB per entry, 32 MiB total by default); it does not reuse unfinished branches. Set `solver.local_reuse_subtrees = false` for the ablation. The optional nonvanishing portfolio may use exact sample zeros or opposite signs to abandon an unsuccessful certificate attempt early; samples never certify nonvanishing.

`solver.local_max_refinements` and `solver.local_max_nodes` override the local discovery defaults of 10,000 refinements and 100,000 visited nodes. Exhausting either cap returns an incomplete result. The enclosing process deadline and memory limit remain binding even when these discovery caps are raised.

Unfinished local stacks can retain learned cuts at the identical rational prefix. These are hints: every seeded cut is projected again and every sector rebuilt. The cache bounds entries, polynomial IDs, prefix bit sizes, and retained bytes; it never treats an unfinished stack as a proof. Set `solver.local_reuse_learned_cuts = false` for the same-engine ablation.

The experimental `solver.local_hint_archive = true` persists bounded cut hints under an explicit `solver.checkpoint_dir`. It defaults to false; `hard_probe --local-hint-archive` enables the experiment. Archives use the exact ordered problem and projection options, canonical sparse polynomials and exact rational prefixes. Imported polynomials are checked and factored again, and all stacks are projected again. Proof verification never reads the archive. Each archive is capped at 8 MiB, with 10-second atomic snapshots and a best-effort final snapshot on a soft stop; reports include load, validation and I/O costs. The archive is disabled, with a reported reason, when caches or learned cuts are disabled, or when `local_descartes_witnesses`, `local_descartes_intervals` or `local_positive_pair_witnesses` is enabled: preserving those modes across restarts also requires their permanent template-admission ledger. Ordinary `local_descartes_one` remains compatible. Corrupt, incompatible or oversized archives are ignored. Restart performance remains experimental.

The opt-in `solver.local_stable_samples = true` retains a bounded pool of visited rational samples while one stack is refined at a fixed ancestor prefix. A sample is reused only when exact root comparisons place it strictly inside a new sector; the ordinary child visitor and all proof obligations still run. This can preserve exact-prefix cache reuse when root intervals tighten. Each pool has limits of 256 samples, 32 KiB and 1,024 numerator-plus-denominator bits per sample; inconclusive comparisons fall back to ordinary sampling after 128 refinements. The verifier independently checks strict sector membership. The option defaults to false; `hard_probe --stable-samples` enables the experiment.

`solver.local_retain_siblings = true` (requires `local_stable_samples = true`; default false) keeps every complete child proof of a stack visit across that visit's refinement rounds. Within one visit the ancestor prefix is fixed and cuts only grow, so each new sector lies inside one old sector; a retained child is moved into the new sector that strictly contains its unchanged rational sample, and its returned obligations are merged exactly as for a fresh visit (same-axis requirements must be among the final cuts, lower ones go to the ancestors). Without retention, every refinement discards all completed siblings and re-explores them at new or uncached prefixes; the exact-prefix subtree cache admits only small subtrees and evicts FIFO. With retention a round also finishes visiting its siblings before restarting, because no completed sibling is wasted; the deferred discovery loop retains in the same way. All retained pools share a budget of proof-tree nodes (a quarter of `limits.memory_mib` counted at 4 KiB per node; about 5 KiB of resident memory per retained node was measured, so retained siblings stay below about a third of the limit); a child declined by the budget is simply revisited later. Once the pool declines a child for memory (budget or per-pool count) or has no room left, the round stops at the ordinary discovery thresholds again instead of finishing its siblings. Reports separate `retained_sibling_budget_drops`, `retained_sibling_capacity_drops` and `retained_sibling_duplicate_drops`. The independent checker replays every reused child at its exact prefix. `SYMGCAD_LOCAL_THRASH_DIAG=1` adds a read-only `thrash` section to the local report: restarts and additions per level, addition events and distinct cuts by origin (the union of every projection rule that has produced the polynomial so far, looked up only in the in-memory factor cache; coefficients of a cut that itself came from a separator are marked `coefficient_of_separator_cut`), completed children discarded or not kept, subtree-cache miss causes and per-level projection seconds. The diagnostic performs no factorization and changes no cache counter.

`solver.local_deferred_projection = true` is a separate opt-in experiment requiring `local_stable_samples = true`. It discovers complete children before projecting the stack, then removes learned cuts that no retained child requires. A whole old child, with its unchanged rational sample and every guard obligation, covers each enlarged sector only after ordinary final projection certifies that sector. The existing checker independently reconstructs the final projection, root union, samples and exhaustive children. Discovery and compaction have finite inventory caps; exceeding them resumes ordinary stack construction, while resource exhaustion remains incomplete. Defaults are unchanged. See [the soundness and limits](../reference/LOCAL_PROJECTION_LIVENESS.md); the captured A446 octic has not been shown to be dispensable.

`solver.local_subtree_cache_mib` and `solver.local_learned_cut_cache_mib` set retained proof and hint budgets, defaulting to 32 and 8 MiB. Their effective sizes cannot exceed 1/16 and 1/128 of the process memory limit. Larger budgets also scale the total node, entry and ID caps. Zero disables retention. Reports expose effective limits and eviction counts.

`solver.local_subtree_cache_entry_nodes` separately sets the maximum nodes in one retained complete conditional proof, from 128 (the default) through 4096. For example, 1024 admits larger proofs without increasing the total cache budget. The 16-level depth limit, 1-MiB payload limit, exact prefix keys and all returned proof obligations remain unchanged. Larger entries can reduce rebuilding but also evict more smaller entries; this is an experimental tuning option, not a guaranteed speedup. Historical inputs retain the 128-node policy. The selected limit is reported and survives serialization and homogeneous reduction; a valid change to this cache policy does not alter verification requirements.

At the first local lifting axis, exact univariate cuts need no lower-dimensional projection. The engine isolates their complete real-root union directly; the verifier checks this zero-dimensional-base condition and every resulting sector. Set `solver.local_base_point_projection = false` for the ablation. Root unions use an ordered queue with exact equality and bisection checks, including coincident or arbitrarily close roots.

The experimental `solver.local_base_univariate_basis = true` replaces irreducible factorization only for bounded, projection-generated guards already in the actual first variable. Initial constraint/split factorization is unchanged. Native square-free blocks enter a separate immutable registry with exact canonical product records; the independent checker replays those identities and every raw projection obligation, then checks the complete real-root union and all sectors. Reducible or repeated blocks are permitted only as empty-prefix base-point cuts, and no zero seam is removed. This requires `local_base_point_projection = true`; combining it with `local_hint_archive = true` is explicitly rejected in v1. The option defaults to false; `hard_probe --base-univariate-basis` enables it. Static size/support declines use ordinary factorization; failure after entering the new algebra stage is a computation failure, and resource exhaustion stays incomplete, without starting another backend. Reports separate decomposition, product reconstruction and root-union costs. This is a tested prototype, not a default or whole-solver performance claim; see [the design and evidence](../reference/BASE_UNIVARIATE_BASIS_PROPOSAL.md).

## Results and verification

JSON results retain the normalized input, variable order, canonical polynomial table, projection levels, rational sample points, and algebraic boundaries. A boundary references a polynomial and its zero-based index among distinct roots in its `index_domain` (`real` by default), with a rational isolating interval at the sample point. Missing lower/upper boundaries mean negative/positive infinity.

`complete_generic` means complete outside an explicit algebraic exceptional set. Lower-dimensional sections are excluded. Specializing a symbolic answer onto an exceptional parameter value requires recomputation after substitution.

The verifier reconstructs projection obligations and checks an exhaustive lifting trace. It checks all real-root gaps, exact rejection witnesses, accepted cells, and coverage accounting. An incomplete result cannot pass verification. `merge = "aggressive"` additionally produces compatibility-only merged cells; certified raw cells and their seams remain available. A same-sign zero of an integrand must not disappear merely because adjacent signs agree.

Production resultants use Symbolica's deterministic integer-Ducos routine, exact low-degree identities, and bounded bivariate interpolation with enough exact images to prove the full polynomial identity. Automatic CRT dispatch is confined to the profiling example because the current Symbolica checkout permits probabilistic early termination there. The separately replayable upstream sign correction in `patches/` is documented but is not applied to the reference checkout. `comparison::compare_generic` validates small decompositions through a certified common refinement, including differing variable orders and reconstructed scale/monotone cells.

## A quadratic opening below a linear fiber

The opt-in `quadratic_ladder` engine accepts one split polynomial, a fixed or
given order, and three final positive unbounded coordinates `y,x,z`. It checks
the signed original identity `F = q*z+B`, where
`q = a*x^2+(b0-b1*y)*x+c`. Strict certificates must prove
`B,a,c,b0,b1>0`; the discriminant of `q` in `x` must be quadratic in `y`
with strictly positive leading coefficient. These are whole-domain
requirements. No sampled sign establishes a premise.

These identities prove that two positive `x` roots open above the larger
discriminant root in `y`. The engine restores exactly five cells above every
verified base cell, including both sides of the original interior `F=0`
sheet. Its typed proof records six positivity certificates and the exact
base decomposition. Verification extracts coefficients afresh, replays the
certificates, verifies the base and checks every restored branch and root
selector. Extra constraints involving these final three coordinates,
multiple split polynomials, homogeneous transport or inconclusive premises
produce an explicit applicability error. Base-only strict constraints are
retained. The [theorem](../reference/POSITIVE_ENDPOINT_QUADRATIC_LADDER_PLAN.md)
specifies the exceptional sections and root conventions.

```sh
symgcad solve examples/quadratic_ladder.toml --output artifacts/ladder.json
symgcad verify artifacts/ladder.json
```

For more complicated coefficients, enable either or both of
`weighted_square_positivity = true` and
`quadratic_component_positivity = true`, together with `positivity = true`.
The latter checks rational positive-semidefinite quadratic components plus
a strictly positive residual. Both options preserve uncertified interior
zero boundaries and default to false.

## Reference corpus and benchmarks

The reference checkouts and generated inputs/results are ignored by Git. Revisions and initial corpus hashes are recorded in `PROVENANCE.toml`.

```sh
nix develop .#reference -c python reference/build_reference.py
mkdir -p artifacts/corpus

  --source DO_NOT_PUSH_REFERENCES/gcad > artifacts/corpus/core-inputs.json

target/release/symgcad corpus --output artifacts/corpus/symbolic \
  --core artifacts/corpus/core-inputs.json
target/release/symgcad bench artifacts/campaigns/core-fast.toml
```

The fixed workload uses `mt2=1,mz2=5/18,s=10,t=-3`. The original symbolic ZZ workload keeps `s,t` symbolic and imposes `s>4,x_i>0`. Both remain distinct completion obligations. The hard topology is A446, with Ax12 as its crossing.

The benchmark runner first freezes reference-completing cases and their orders, then performs repeated fresh-process comparisons. The parity ratio uses matched projection, lifting and merging phases; preparation and process wall times are reported separately. See `reference/README.md` for campaign configuration. Local milestone commits do not imply that unresolved corpus cases have been solved.

`BENCHMARKS.md` records validated milestones, artifact hashes, and the limits of each performance claim. The Nix shell includes `perf` and Valgrind for profiling captured algebra workloads.

## Library certificate budgets

`domain::CertificateOptions` lets a caller raise `work_limit` to 1,000,000,000
and `bernstein_coefficients` to 262,144 for larger exact nonvanishing proofs.
Defaults remain 1,000,000 work units and 4,096 coefficients. Other portfolio,
polynomial, depth and node limits are unchanged; solver defaults are unchanged.
These are explicit finite allowances, not guarantees that a proof will finish.
Use a caller-owned wall-time and memory supervisor for expensive inputs.

The exact chosen options are serialized with each `DomainCertificate` and
checked again by `verify_certificate`. Verification can perform the same costly
exact arithmetic; lowering a stored allowance can make replay fail. A bounded
discovery miss remains inconclusive and is never a sign or zero certificate.
