# One-hour original-problem queue

`examples/slow_suite.rs` executes every case labelled `slow` in
`tests/corpus_classification.json`. It retains aliases and exact original-file
and normalized-mathematics hashes. The checked-in `tests/slow_options.json`
contains solver settings and mathematical hashes only; it does not contain
reference polynomials, private artifact paths, or proofs. Each recipe also
binds the original name and explicit fixed order. The reference corpus
must first be regenerated by the documented setup workflow.

After building an immutable `symgcad` executable, run:

```sh
scripts/test.sh slow --executable /absolute/path/to/symgcad \
  --output artifacts/slow-suite-one-hour-02 --cpus 0,1,2,3 \
  --memory-mib 8192 --verification-seconds 600
```

Choose CPUs available to the process. The queue rejects duplicate CPU slots,
more than 16 concurrent workers, and aggregate declared worker memory above
64 GiB. Each slot is pinned to one CPU. Four 8 GiB slots use at most 32 GiB
of declared worker memory. `--prepare-only` performs the original-file,
mathematical, order, group, and homogeneous-reduction checks and writes the
prepared inputs without starting solves. A private completion aggregate is
not required; `--aggregate` optionally audits the classification against one.
`--corpus-root PATH` selects another regenerated tree containing `fixed/`
and `symbolic/`. New importer versions can serialize additional solver
defaults. A changed original-file hash is accepted only after the exact
normalized mathematical hash, original name and explicit fixed order all
match. Both the historical and actual byte hashes, and a serialization-change
flag, are retained in the prepared manifest; the runner never pretends the
byte hashes matched.

Each original receives a fresh cold checkpoint namespace and a one-hour
public solve budget, including its ordering search. The generic recipes use
a 300-second, 256-rollout search with seed zero. Known full-original orders
for A317, A318, A377 and A446 are retained as explicit recipes. The local
limits of 20 million refinements and 200 million speculative nodes avoid
the premature 10,000-refinement limit seen in earlier short trials. They
remain finite, and the process memory and time limits remain binding.

The standard completion campaign writes an append-only attempt ledger with
input, executable, result and verification hashes. If a complete result is
exported but its campaign has no verification time left, a fresh worker may
verify that same immutable proof for a separate bounded 600 seconds. Its
report records the proof hash before and after verification. No incomplete
or unverifiable result earns completion credit.

`queue.json` is atomically updated after each transition. The status
`finished` means that the bounded attempt finished; it is **not** a claim
that the original was solved. A separate `verdict` is `verified`,
`incomplete`, or `infrastructure_failed`. Completion requires the standard
or supplemental verification process to have succeeded, matching input,
proof and verification hashes, matching original mathematics/order, and an
exact proof/verification cell-count match. The final audit rechecks this
evidence, writes `summary.json`, and returns a nonzero exit status if any
original remains unverified. Streaming evidence audits are additional
supervisor work outside the separately bounded solve and verifier workers.
Reusing the same command and output directory
resumes pending or infrastructure-failed attempts, while preserving finished
attempts, including mathematical failures. The executable, classification,
prepared inputs, resource settings and finished-ledger hashes must match.
A lock prevents two queue processes from owning the same directory.
The output also snapshots the classification, so later metadata updates do
not erase the campaign's original inventory.

An existing queue, including the first frozen helper's older manifest, can
be audited without modifying any running or saved campaign:

```sh
cargo run --release --example slow_suite -- \
  --audit-queue artifacts/slow-suite-one-hour-01/queue.json \
  --classification tests/corpus_classification.json \
  --output artifacts/slow-suite-one-hour-audit-02
```

The audit output must be new. It saves the queue/classification/preparation
snapshots and `audit.json`; pending/running entries stay pending. Its exit
status is nonzero until every original is verified. If the tracked
classification has changed, pass the exact `classification.json` copied
by an earlier audit or preparation of that queue. The live first queue's
initial read-only audit is retained under
`artifacts/slow-suite-one-hour-audit-01/`.

The 10 October 2026 audit of the first four finished attempts found no new
complete result. Symbolic A317, A318, A446 and Ax12-A446 each timed out after
3600.024 seconds; no result file, proof or verification was available. Their
recorded peak resident memory was respectively 1364.1, 1413.2, 1944.3 and
699.1 MiB. These are censored attempts, not solved times or speedup ratios.

four finished attempts, four further runs active and twenty pending.
